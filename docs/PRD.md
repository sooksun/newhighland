# PRD — ระบบประเมินและรับรองโรงเรียนพื้นที่ลักษณะพิเศษ (newhighland) ปีงบประมาณ 2569

> เอกสารความต้องการผลิตภัณฑ์ (Product Requirements Document)
> โครงการ: ปรับปรุงระบบประเมินโรงเรียนพื้นที่ภูเขาสูงในถิ่นทุรกันดาร และโรงเรียนพื้นที่เกาะ
> เจ้าของระบบ: สำนักนโยบายและแผนการศึกษาขั้นพื้นฐาน (สนผ.) สพฐ.
> เวอร์ชัน: 0.1 (ร่างแรก) — วันที่ 2 มิ.ย. 2569 (พ.ศ.)
> สถานะ: รอการพิจารณา / ยังไม่เริ่มเขียนโค้ดจริง

## 1. ภาพรวมและวัตถุประสงค์

ระบบเดิม (`D:\laragon\www\highland`, โดเมน `ssra.info/saoadmin/`) เป็นระบบที่สร้างด้วย **PHPRunner**
ทำหน้าที่คัดกรองและประเมินโรงเรียนพื้นที่ลักษณะพิเศษ 2 ประเภท คือ
**โรงเรียนพื้นที่ภูเขาสูงในถิ่นทุรกันดาร** และ **โรงเรียนพื้นที่เกาะ**

ปีงบประมาณ 2569 สพฐ. ต้องการเปิดระบบใหม่เพื่อรองรับ 2 กระบวนการที่ต่างกัน:

1. **เปิดประเมินใหม่** สำหรับโรงเรียนที่ "ตกหล่น" ยังไม่เคยได้รับการคัดกรอง — ต้องประเมินครบกระบวนการ
   (ปักหมุด → วัดความสูง/ระยะทาง → กรอกแบบ 16 ข้อ → คิดคะแนน → พิมพ์ผล)
2. **ยืนยันการคงอยู่** สำหรับโรงเรียนที่เป็นพื้นที่พิเศษอยู่แล้ว — เพียงยืนยันสถานะ
   (ไม่ยุบ / ไม่เลิก / ไม่รวม) แล้วให้ "สำนักงานเขตพื้นที่การศึกษา" รับรอง

ระบบใหม่ (`D:\laragon\www\newhighland`) จะ **เขียนด้วย PHP ล้วน + MySQL (hand-written)**
โดย **ใช้ฐานข้อมูลเดิม `ssrainfo_ssra`** และ **ระบบ login/สิทธิ์เดิม** เพิ่มข้อมูลปี 2569 เข้าไป

### เป้าหมายของการปรับปรุง (ทำไมต้องเขียนใหม่ ไม่ใช้ PHPRunner)
- แยก codebase ที่อ่าน/ดูแลง่าย ไม่ผูกกับ generator ของ PHPRunner
- แก้ช่องโหว่ความปลอดภัยจากระบบเดิม (SQL injection จาก string interpolation — ดู §10)
- พารามิเตอร์ปีการศึกษา/ปีงบประมาณ ไม่ฮาร์ดโค้ด (ระบบเดิมฮาร์ดโค้ด 2566/2567 หลายจุด)
- รองรับ 4 กระบวนการของปี 2569 ในที่เดียว

## 3. ผู้ใช้และสิทธิ์ (Roles)

ใช้ระบบสิทธิ์เดิม (ตาราง `user`, `ssra_ugmembers`, `ssra_ugrights`, และ `master_saonew` สำหรับ login ระดับเขต)

| Role | login จาก | ขอบเขตข้อมูล | ความสามารถ |
|---|---|---|---|
| **โรงเรียน** | `user` (`sc_id`) | เฉพาะโรงเรียนตนเอง (`WHERE sc_id = session.sc_id`) | ปักหมุด, กรอกแบบประเมิน, ยืนยันการคงอยู่, พิมพ์ |
| **เขตพื้นที่ (สพป./สพม.)** | `master_saonew` (`code`) | โรงเรียนในสังกัด (`sao_code`) | ดู, **รับรอง** ผลโรงเรียน (`sao_proved`, `confirmstatus`) |
| **สพฐ. (Admin)** | `user.level`/group admin | ทุกโรงเรียน | ดูทั้งหมด, ตั้งค่า, ประกาศผล (`spt_commit`), export |

กลไกสิทธิ์ในโค้ดเดิม: ฟังก์ชัน `IsAdmin()` + `$_SESSION["sc_id"]` + `BeforeQueryList` กรองด้วย `sc_id`
(ดู `include/highland_eval_events.php` บรรทัด 1170–1180) — ระบบใหม่จะทำ middleware ตรวจสิทธิ์ให้ชัดเจนกว่าเดิม

## 4. สถาปัตยกรรมเทคนิค

### 4.1 Stack
- **ภาษา:** PHP 8.x (ล้วน, ไม่ใช้ framework เต็ม) — โครง MVC เบา ๆ เขียนเอง
- **ฐานข้อมูล:** MySQL/MariaDB `ssrainfo_ssra` (ใช้ร่วมกับระบบเดิม)
- **DB access:** PDO + prepared statements (เลิกใช้ mysqli string interpolation)
- **Frontend:** Bootstrap 5.3 (ตามระบบเดิม) + jQuery (เท่าที่จำเป็น)
- **แผนที่/ความสูง:** Google Maps JS API + Places + Elevation + Directions (คีย์เดิม — ดู §13)
- **PDF:** mPDF (มีอยู่แล้วใน `highland/mpdf/vendor`) + ฟอนต์ไทย (Sarabun)

### 5.2 ตารางประเมินพื้นที่สูง
- **`highland_eval`** — PK ร่วม `(sc_id, acadyears)` 1 แถว = 1 โรงเรียน/ปี
  - ข้อมูลทั่วไป: `sc_names, director_name, director_tel, editor_name, sao_names, adresss, moo, subdistrict, district, provinces, lgo`
  - นักเรียน: `stu_kinder, stu_prim, stu_second, stu_high, stu_sum`, ชาติพันธุ์ `stu_hilltrib, stu_hilltrib_group`, พักนอน `stu_sleep_boy/girl/sum`
  - ภูมิศาสตร์ (จากแผนที่): `lat, lng, highest, average_height, distance_to_province`
  - คำตอบ 16 ข้อ: `citeria01..citeria16` (+ `citeria041`) และเอกสารแนบ `citeriaNN_refdoc`
  - คะแนน: `score01..score16`, `sum_score`, `highland_type` (0=พื้นราบ,1,2,3)
  - สถานะ/รับรอง: `status, confirmstatus, confirmcomment, fail_reason`,
    เขต: `sao_proved2567, sao_comment2567`, สพฐ.: `spt_commit, spt_comment`,
    การคงอยู่/ยุบรวม: `opened, sc_merged, sc_merged_id, sc_merged_status, ssra_old`
- **`highland_eval_hilltrib`** — PK ร่วม `(sc_id, acadyears, hilltrib)`; `hilltrib_number` = จำนวนนักเรียนกลุ่มนั้น
  (ใช้คำนวณข้อ 11 = ร้อยละชาติพันธุ์, ข้อ 12 = จำนวนกลุ่ม)

### 5.3 ตารางประเมินพื้นที่เกาะ
- **`island_eval`** — โครงคล้าย `highland_eval` แต่: ไม่มี `highest/average_height` (ไม่ใช้ความสูง),
  มีข้อมูลครู `teacher, panuk, gov_employee, ...`, คำตอบ `citeria01..citeria15` (15 ข้อ),
  `island_type` แทน `highland_type` — **เกณฑ์/คะแนนรอยืนยันจากเอกสารส่วนที่ 2**

### 5.4 ฟิลด์สำหรับ "การคงอยู่ / ยุบ-เลิก-รวม" (ส่วนที่ 3–4)
| ฟิลด์ | ความหมาย |

## 6. ส่วนที่ 1 — ประเมินโรงเรียนพื้นที่สูง **ใหม่** ปี 2569 (รายละเอียดหลัก)

### 6.1 ขั้นตอน (User Flow)
```
[1] โรงเรียน login → เลือกสังกัด (สพป./สพม.) → เลือกโรงเรียนจาก dropdown (กรองตาม sao_code)
        ↓
[2] หน้าแผนที่ปักหมุด (ssar_search.php เดิม)
    - ค้นหาสถานที่ (Google Places) / คลิกปักหมุดตำแหน่งโรงเรียน
    - ระบบดึงค่าความสูง ณ จุด (Elevation API) → lat, lng, location_high
    - "บันทึกและตรวจสอบ" → POST เก็บลง school_location (map_uplatlng.php เดิม)
        ↓
[3] หน้าวัดความสูง/ระยะทาง (ssar_elevation.php เดิม)
    - ลากเส้นทางรถยนต์ โรงเรียน → ศาลากลางจังหวัด (Directions API, sample 512 จุด)
    - หา "ความสูงสูงสุดตลอดเส้นทาง" (highest) และ "ระยะทางรวม" (distance ×1.0345)
    - ตัดสิน: highest > average_height(จังหวัด)  หรือ  highest > 500 ม.  → "ภูเขา"; ไม่งั้น "พื้นราบ"
    - "บันทึก" → POST เก็บ/สร้างแถวใน highland_eval (map_upcomment.php เดิม)
        ↓
[4] เงื่อนไขแยกทาง:
    - ถ้า "พื้นราบ" (highest < เกณฑ์) → จบการประเมิน (ไม่เป็นพื้นที่สูง)
    - ถ้า "ภูเขา" (highest >= เกณฑ์) → ไปกรอกแบบประเมิน
        ↓
[5] แบบประเมิน 16 ข้อ (highland_eval_add/edit.php เดิม) — มี 11 แท็บ (ดู §6.3)
    - กรอกข้อมูลทั่วไป, นักเรียน, ชาติพันธุ์, ภูมิศาสตร์, คมนาคม, สาธารณูปโภค ฯลฯ
    - แนบไฟล์เอกสาร/ภาพ (citeriaNN_refdoc) ตามที่เกณฑ์กำหนด
        ↓
[6] บันทึก → ระบบคิดคะแนน 16 ข้อ + sum_score + highland_type (ScoreService) — §6.5
        ↓
[7] พิมพ์แบบประเมิน (PDF, mPDF) — §9
        ↓
[8] เขตพื้นที่ตรวจ + รับรอง (sao_proved) → สพฐ. ประกาศผล
```

### 6.2 ไฟล์ระบบเดิมที่เกี่ยวข้อง (ใช้ศึกษา/พอร์ต)
| ไฟล์เดิม | หน้าที่ | พอร์ตเป็น |

### 6.5 สูตรคิดคะแนน (Canonical — อ้างอิง `BeforeEdit` ใน `highland_eval_events.php`)
> ใช้ `BeforeEdit` เป็นต้นแบบที่ถูกต้อง (เวอร์ชัน `BeforeAdd` มีบั๊ก เช่น ใช้ตัวแปรก่อนกำหนดค่า — ดู §10)
> `format_number(x,2)` = ปัดทศนิยม 2 ตำแหน่ง

```
ข้อ 1 (เต็ม 30): ถ้า citeria01>=500 หรือ citeria01>=average_height:
                 c = min(citeria01, 500);  score01 = 15 + (c*15/500)      # = 30 ที่ 500m
                 มิฉะนั้น score01 = 0                                       # (พื้นราบ)
ข้อ 2 (5):  map {1→5, 2→4, 3→3, 4→2, 5→0}
ข้อ 3 (5):  map {1→5, 2→4, 3→3, 4→0}
ข้อ 4 (5):  ถ้า citeria04==2 → citeria041=0;  score04 = min(citeria041, 5)
ข้อ 5 (5):  score05 = min(citeria05, 80) * 5 / 80
ข้อ 6 (5):  map {1→5, 2→4, 3→3, 4→1, 5→1}
ข้อ 7 (6):  ใช้ค่าสูงสุดของตัวเลือกที่เลือก (comma list) → map {1→6,2→5,3→4,4→3,5→2,6→1}
ข้อ 8 (3):  max → map {1→3, 2→0}
ข้อ 9 (3):  max → map {1→3, 2→2, 3→1, 4→0}
ข้อ 10 (3): max → map {1→3, 2→2, 3→1, 4→0}
ข้อ 11 (5): pct = min( SUM(hilltrib_number)*100/stu_sum , 100);  score11 = pct*5/100
ข้อ 12 (5): score12 = min( COUNT(กลุ่มชาติพันธุ์) , 5 )
ข้อ 13 (5): pct = min( citeria13*100/stu_sum , 50 );  score13 = pct*5/50
ข้อ 14 (5): score14 = min(citeria14, 50) * 5 / 50
ข้อ 15 (5): c = min(citeria15, 3);  map {1→3, 2→4, 3→5}
ข้อ 16 (5): map {1→5, 2→0}

sum_score = Σ score01..score16
highland_type = (sum_score>=70 → 3) ; (>=60 → 2) ; (>=50 → 1) ; else 0
```
**เกณฑ์ตัดสิน:** `sum_score >= 50` = เป็นโรงเรียนพื้นที่สูงในถิ่นทุรกันดาร
(50–59 = ยุ่งยาก, 60–69 = ยุ่งยากมาก, 70+ = ยุ่งยากมากที่สุด)

## 8. ส่วนที่ 3 และ 4 — รับรอง "การคงอยู่" (ไม่ยุบ/เลิก/รวม)

> ส่วนที่ 3 = พื้นที่สูง (อ้างอิง `รายชื่อโรงเรียนพื้นที่สูงในถิ่นทุรกันดาร 2566.xlsx`)
> ส่วนที่ 4 = พื้นที่เกาะ (อ้างอิง `รายชื่อโรงเรียนพื้นที่เกาะ 2566.xlsx`)
> ทั้งสองส่วนใช้ flow เดียวกัน ต่างกันที่ตาราง (`highland_eval` vs `island_eval`) และรายชื่อตั้งต้น

### 8.1 Flow
```
[1] โหลดรายชื่อโรงเรียนที่เป็นพื้นที่พิเศษอยู่แล้ว (จากปี 2566 / สถานะปัจจุบัน)
        ↓
[2] โรงเรียน login → เห็นข้อมูลตนเอง → ยืนยัน:
    - ยังเปิดอยู่/คงอยู่ (opened)
    - ไม่ถูกยุบ/เลิก/รวม  หรือ ระบุสถานะ (sc_merged, sc_merged_id, sc_merged_status, merge_status)
        ↓
[3] เขตพื้นที่ (สพป./สพม.) ตรวจสอบ → รับรอง (sao_proved2569 + ความเห็น)
        ↓
[4] สพฐ. รวบรวม/ประกาศคงสถานะ (spt_commit)
```

### 8.2 ข้อมูลที่ใช้
- รายชื่อตั้งต้น: import จาก xlsx 2566 (หรือดึงจาก `highland_eval`/`island_eval` ที่ `sum_score>=50` ปีก่อน)
- ฟิลด์รับรอง: `opened, sc_merged*, sao_proved*, confirmstatus, spt_commit` (ดู §5.4)
- โครงสร้าง xlsx รายชื่อพื้นที่สูง: `รหัสโรงเรียน, โรงเรียน, จังหวัด, ระดับความสูง ณ จุดที่ตั้ง, ระดับความสูงเฉลี่ยจังหวัด, ระยะทางถึงศาลากลาง, คะแนนรวม`
- โครงสร้าง xlsx รายชื่อพื้นที่เกาะ: `ที่, Sc Id, รหัสโรงเรียน, ตำบล, อำเภอ, จังหวัด, สังกัด, ขนาด, จำนวนนักเรียนปี 65, ชื่อโรงเรียน, ...`

## 12. เกณฑ์ความสำเร็จ (Acceptance — ส่วนที่ 1)
1. โรงเรียนเลือกสังกัด→โรงเรียน→ปักหมุด→ได้ค่า lat/lng/ความสูง ณ จุด บันทึกได้
2. วัดเส้นทางถึงศาลากลาง ได้ `highest` + `distance` และตัดสินภูเขา/ราบถูกต้องตามเกณฑ์ (>avg หรือ >500)
3. กรณีพื้นราบ → จบ; กรณีภูเขา → เข้าแบบประเมินได้
4. กรอก 16 ข้อ + แนบไฟล์ + บันทึก → คะแนนตรงกับสูตร §6.5 ทุกข้อ และ `highland_type` ถูกต้อง
5. เขตรับรองได้, พิมพ์ PDF ได้ครบถ้วน
6. ทุก query เป็น prepared statement, ไม่มีปีฮาร์ดโค้ด
